# 기능과 데이터 기준

Memorize Helper는 정적 성경 본문으로 암송 연습을 하고, 로그인한 사용자의 날짜별 암송 범위를 저장합니다.

## 화면

| 경로                    | 기능                                                |
| ----------------------- | --------------------------------------------------- |
| `/`                     | 자료 목록, 자료별 암송 진행률                       |
| `/script/:id`           | 줄별·전체 가리기/열기, 장·단락 구분, 암송 기록 입력 |
| `/records`              | 주간·월간 기록 조회, 추가·수정·삭제                 |
| `/updates`              | 현재 업데이트 안내                                  |
| `/oauth/kakao/callback` | 카카오 로그인 결과와 원래 화면 복귀                 |

자료 읽기와 개인 설정에는 로그인이 필요하지 않습니다. 기록 저장·관리는 카카오 로그인과 Supabase 테이블·RLS 설정이 필요합니다. 자료 추가·편집 UI와 묵상 메모 저장 기능은 없습니다.

## 기록 정책

- 사용자당 날짜별 한 기록을 저장합니다. 여러 자료를 같은 날짜에 별도 기록하는 구조는 아닙니다.
- 신규 추가는 기존 날짜 기록을 덮어쓰지 않습니다. 날짜 충돌을 안내합니다.
- 본문 화면에서 오늘 기록을 열면 기존 범위를 수정합니다. 다른 자료 화면이어도 원래 자료 ID를 유지하고 수정 대상 자료를 안내합니다.
- 암송 자료를 변경하려면 기록 관리 화면에서 자료를 선택합니다.
- 오늘과 지난 날짜를 기록할 수 있으며 미래 날짜는 입력하지 않습니다. 날짜는 기기의 로컬 시간 기준입니다.
- 시작·마지막 장절은 양의 정수이고 시작이 마지막보다 뒤에 올 수 없습니다. 실제 존재하는 장절인지의 전체 성경 기준 검증은 구현하지 않았습니다.

본문 입력의 기본 범위는 열어본 절의 최소·최대 장절입니다. 중간에 열지 않은 절이 있어도 연속 범위로 제안하므로 저장 전에 확인해야 합니다. 가리기/열기 자체로 기록이 자동 저장되지는 않습니다.

진행률은 해당 자료에 저장된 범위가 덮는 고유 절 수를 전체 절 수로 나눈 백분율이며 반올림합니다. 여러 날짜에 같은 절을 기록해도 한 번만 계산합니다. 암송 능력을 자동 평가한 수치가 아닙니다.

## 개인 설정

글자 크기는 15, 18, 22, 28, 36, 44, 52, 60px입니다. 다크 모드, 소제목 가리기, 마지막 기록에서 시작 설정도 제공합니다. 설정은 브라우저 `localStorage`에 저장되므로 다른 기기나 계정에 동기화되지 않습니다.

‘마지막 기록에서 시작’을 켜면 자료의 가장 최근 기록 날짜에 저장된 마지막 절로 이동합니다. 본문 공개 상태와 열어본 절은 화면 상태이며 자료를 바꾸면 초기화합니다.

## 본문 자료

| 자료                    | 범위·번역본              | 단락 수 | 절 수 |
| ----------------------- | ------------------------ | ------: | ----: |
| 산상수훈                | 마태복음 5–7장, 개역개정 |      17 |   111 |
| The Sermon on the Mount | Matthew 5–7, ESV         |      22 |   111 |
| 로마서 8장              | 로마서 8장, 개역개정     |       3 |    39 |

자료는 `public/scripts/*.json`, 목록 정보는 `src/data/database.ts`에 있습니다. 각 `lines` 항목은 번호가 붙은 한 절을 담고 소제목은 `label`에 둡니다. 현재 장절은 문자열에서 추출하며 `Matthew`, `마`, `롬`을 인식합니다. 다른 책과 일반 문장의 기록 지원에는 추가 구현이 필요합니다.

줄을 가리면 첫 번째 공백 구분 토큰만 보입니다. 현재 본문에서는 절 번호가 남습니다. 키보드로 줄을 열고 닫는 기능과 대화상자 포커스 관리 개선은 후속 과제입니다.

## 검증 범위

`npm test`는 기록의 자료 연결, 날짜 충돌, 계정 전환, 조회 실패·재시도, 자료 전환, 전체 기록 페이지 조회와 본문 장절 범위를 검증합니다. 실제 카카오 인증·운영 DB의 RLS·판본 원문의 문장 정확성은 별도 검증이 필요합니다.
