# 업데이트 노트 DB 연결

업데이트 노트는 `public.update_notes`에서 읽습니다. 화면 문구는 앱 코드 대신 DB에 저장하고,
앱의 첫 안내 팝업과 `/updates` 이력이 같은 데이터를 사용합니다.

## 적용 순서

1. 사용하는 Supabase 프로젝트의 SQL Editor를 엽니다.
2. [테이블·정책·초기 데이터 SQL](../supabase/migrations/202610110001_update_notes.sql)을 실행합니다.
3. Table Editor에서 `update_notes`의 RLS와 SELECT 전용 공개 정책을 확인합니다.
4. 초기 데이터 두 개와 새 `0.2.0` 안내의 세 항목을 확인합니다.
5. 앱 0.2.0을 실행하고 첫 팝업과 `/updates`에서 새 안내를 확인합니다.

이 SQL은 기존 암송 기록 테이블을 변경하지 않습니다. 같은 SQL을 다시 실행해도 이미 있는 ID의
내용을 덮어쓰거나 중복 생성하지 않습니다. 운영 데이터가 이미 수정된 경우 의도적으로 보존합니다.

현재 작업 환경에는 Supabase 관리 연결이 없어 운영 프로젝트 적용은 별도로 필요합니다.
이전 SQL은 임시 PostgreSQL 17 환경에서 검증했습니다. 실제 Supabase 프로젝트에서도 아래
권한 검증을 수행한 뒤 운영에 사용합니다.

## 구조와 공개 규칙

| 필드 | 의미 |
| --- | --- |
| `id` | 업데이트 고유 ID. 영문 소문자·숫자·하이픈 사용 |
| `app_version` | 해당 안내를 볼 수 있는 최소 앱 버전. `0.2.0`처럼 숫자 세 부분 |
| `title` | 안내 제목 |
| `introduction` | 소개 문구 |
| `items` | 순서가 있는 JSON 배열. 각 항목에 `icon`, `title`, `description` |
| `published` | 공개 여부. 기본은 비공개 |
| `published_at` | 공개 시각·이력 정렬 기준. 미래 시각이면 공개 대기 |

공개 읽기는 `published = true`이고 공개 시각이 현재보다 늦지 않은 행만 허용합니다.
익명·로그인 사용자는 SELECT만 허용되고 INSERT·UPDATE·DELETE 권한이 없습니다.
작성은 당분간 Supabase Dashboard/제한된 운영 경로를 사용합니다. 관리자 편집 화면은 후속 기능입니다.

앱은 공개 시각 내림차순, 동일 시각이면 ID 내림차순으로 읽습니다. 현재 앱보다 높은 버전의
안내는 표시하지 않습니다. 이 버전 필터는 화면 호환용이며 비공개 데이터 보안 정책이 아닙니다.

`items` 예시:

```json
[
  {
    "icon": "✓",
    "title": "기록으로 쌓이는 작은 성취",
    "description": "첫 기록과 연속 기록 목표를 확인할 수 있어요."
  }
]
```

문구는 Vue 텍스트로 렌더링합니다. HTML·Markdown 삽입을 지원하지 않습니다.
테이블은 JSON 배열 여부를 검사하고, 앱은 각 항목의 문자열 형식도 확인합니다.
형식이 잘못된 응답에는 오류와 재시도를 표시합니다.

## 기존 안내 이전과 숨김 설정

- 기존 안내 ID `2026-08-11-memorization-experience`와 내용을 초기 데이터로 보존했습니다.
- 이번 안내는 `2026-10-11-reading-calendar-achievements`, 앱 버전 `0.2.0`입니다.
- ‘다시 보지 않기’는 `mh_hide_update_<DB의 id>`를 기기 `localStorage`에 저장합니다.
- 기존 ID를 유지하므로 이전에 숨긴 안내는 다시 팝업으로 열리지 않습니다.
- 새 ID의 안내는 기존 숨김 설정과 독립적으로 표시됩니다.
- 팝업을 닫기만 하면 그 페이지 이용 중에는 다시 열리지 않고, 새 방문에서는 다시 표시될 수 있습니다.
- `/updates`에서는 숨김 여부와 관계없이 해당 앱에 맞는 공개 이력을 읽을 수 있습니다.
- DB 조회 실패 시 자동 팝업은 열지 않습니다. `/updates`에서 오류·재시도를 제공합니다.

## 다음 안내 작성

새 내용을 작성할 때는 새 ID로 비공개 초안을 만듭니다. `app_version`을 해당 기능이 포함된
앱 버전으로 지정하고, 세부 항목과 화면 문구를 검토한 뒤 공개합니다.
기존 ID의 문구를 고치면 이력 내용은 갱신되지만 이미 숨긴 사용자에게 새 팝업을 띄우지는 않습니다.
새 안내가 필요하면 새 ID를 사용합니다.

DB 안내를 게시하는 것만으로 앱 코드가 배포되는 것은 아닙니다. 앱 버전과 안내의 내용이 일치하는지
확인합니다. 앱 버전 표시는 계속 `package.json`을 기준으로 합니다.

## 검증

- 익명·사용자 A/B가 공개 안내를 읽고, 초안·예약 공개 행은 읽지 못하는지 확인.
- 각 사용자로 INSERT·UPDATE·DELETE를 직접 시도해 거절되는지 확인.
- 새 안내 팝업·버전별 숨김·이력·이전 숨김 설정 보존 확인.
- 앱보다 높은 버전의 안내가 표시되지 않는지 확인.
- 테이블 미적용·네트워크 실패·빈 이력·잘못된 JSON의 상태와 재시도 확인.

`tests/update-notes.spec.js`는 브라우저 동작을 가짜 API로 검증합니다.
`tests/sql/update-notes.sql`은 독립된 PostgreSQL 테스트 DB에서 이전 SQL의 반복 실행·공개 RLS·
쓰기 거절을 검증합니다. 테스트 SQL은 테스트 역할을 생성하므로 운영 DB에서 실행하지 않습니다.
