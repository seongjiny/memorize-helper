# 1-1. 성경 DB화

상태: 기획 초안. 어드민의 구절·자료 관리 기반 작업입니다.

## 목표와 접근

본문의 판본·책·장·절을 문자열 추측 없이 식별하고, 자료 구성과 장절 검증에 같은 기준을
사용합니다. 첫 이전 대상은 현재 자료의 마태복음 5–7장과 로마서 8장입니다.
66권 전체를 먼저 수집하는 것은 필수 선행 조건이 아닙니다.

1. 현재 JSON을 명시적 장절 데이터로 구조화합니다.
2. 동일 인터페이스로 정적 데이터와 DB 데이터를 읽는 경계를 준비합니다.
3. 검수한 일부 본문과 기존 자료를 DB로 이전합니다.
4. 기록·진행률의 일치와 권한을 확인한 뒤 읽기 경로를 전환합니다.
5. 자료 편집 어드민을 연결하고, 판본 이용 조건에 맞춰 본문 범위를 확대합니다.

구조화된 정적 데이터까지만으로도 시험이나 범위 검증을 개선할 수 있습니다.
운영자가 배포 없이 자료를 바꿔야 할 때 서버 DB와 관리 UI가 필요합니다.

## 출처·판본 이용 조건

- 개역개정·ESV 등 판본마다 수집·저장·재배포·공개 API·표시·다운로드 조건을 확인합니다.
- 현재 저장소에 본문이 있다는 사실만으로 전체 판본을 DB에 저장해도 된다고 판단하지 않습니다.
- 원문 제공처, 이용 근거, 허용 범위, 표시할 저작권 문구, 검수 일자를 기록합니다.
- 권한이 확인되지 않은 판본은 공개 이전 대상에서 보류합니다. 허용된 데이터로 기술 검증은 진행 가능합니다.
- 생성형 이미지나 생성형 텍스트를 성경 원문 출처로 사용하지 않습니다.

## 최소 데이터 설계 제안

다음은 개념 설계이며 실행용 SQL이 아닙니다. 실제 제약·정책은 이전 단계에서 작성합니다.

| 개념 / 테이블 후보 | 주요 필드·역할 |
| --- | --- |
| `bible_editions` | 판본 ID, 언어, 표시명, 출처, 이용 조건·표시 문구 |
| `bible_books` | 언어와 무관한 책 ID, 정렬 순서, 한글/영문 표시명 |
| `bible_edition_revisions` | 판본 데이터의 고정된 검수 버전, 상태, 생성 시각 |
| `bible_verse_texts` | 판본 검수 버전, 책 ID, 장, 절, 본문 |
| `passages` | 기존 `script_id`와 호환하는 안정적 자료 ID |
| `passage_revisions` | 자료 제목·설명·판본 검수 버전·공개 상태·변경 버전 |
| `passage_blocks` | 자료 버전, 순서, 단락 소제목 |
| `passage_block_verses` | 단락, 본문 절 참조, 표시 순서 |

한 절의 키는 `(edition_revision_id, book_id, chapter, verse)`이며 중복을 허용하지 않습니다.
책 ID를 같게 써도 번역본의 본문은 각각 저장합니다. 서로 다른 판본의 절 구분이 항상 같다고
가정하지 않고 판본별 누락·분할 절의 지원 정책을 검수합니다. 첫 대상은 일반 정수 절 번호 범위로
제한하고, 다른 표기 체계를 가져올 때 스키마 지원을 먼저 확장합니다.

소제목은 절 본문에 섞지 않습니다. 책 이름의 언어 차이와 자료의 표시 제목도 분리합니다.
단락 사이에 동일 절을 중복 배치하지 않도록 검사하고 전체 순서를 명시합니다.

첫 단계 자료는 현재 기록 모델에 맞춰 하나의 책·하나의 판본으로 제한합니다.
여러 책을 엮는 자료는 기록 범위 모델을 먼저 변경해야 합니다.

## 공개·변경·보관 정책

- 게시된 본문 버전은 고정하고 수정은 새 초안/새 버전으로 진행합니다.
- 자료는 게시 버전을 가리킵니다. 검수 중인 원문이 사용자 화면에 섞이지 않게 합니다.
- 본문 오탈자 수정과 자료 범위 변경은 구분합니다. 범위 변경은 진행률 분모에 영향을 줍니다.
- 기존 자료 범위를 크게 바꿀 때는 새 자료 ID를 추천합니다. 기존 기록의 의미를 유지합니다.
- 자료 보관 시 신규 목록 노출을 중단하되 과거 기록의 제목·범위는 계속 표시합니다.
- 익명·일반 사용자는 공개 자료와 허용된 공개 본문만 읽습니다. 초안과 관리 이력은 거절합니다.
- 이전 공개 버전을 계속 조회할 수 있는지와 다운로드 허용 여부는 판본 이용 조건에 맞춥니다.

## 기존 기록 이전과 호환

- 기존 `script_id` 세 개를 유지합니다. 이름만 바뀌었다고 기록을 새 자료로 연결하지 않습니다.
- 문자열 `book`은 명시적 책 ID로 매핑합니다. 알 수 없는 값은 검수 목록으로 분리합니다.
- 기록에 자료 버전 연결이 필요합니다. 기존 기록은 이전 시 기준 버전에 연결하고, 새 기록에는
  화면에서 선택한 게시 버전을 저장하는 방향을 제안합니다.
- 서로 다른 자료 버전의 기록 범위를 현재 자료 진행률에 어떻게 반영할지 정책을 정합니다.
  첫 이전에서는 자료 범위를 유지해 결과를 바꾸지 않습니다.
- 기록을 자동 삭제하거나 날짜 충돌을 자동 덮어쓰지 않습니다.
- 기존 자료와 새 본문을 사용자별 기록 예제로 대조합니다. 이전 전후 진행률과 장절이 같아야 합니다.
- DB 장애 시 자동으로 다른 버전의 JSON으로 전환하지 않습니다. 오류·재시도를 제공하고,
  복구 시에는 검수된 동일 데이터 버전으로 전환합니다.

## 하위 작업과 이전 절차

- [ ] 판본 출처·이용 조건·표시 문구 확인.
- [ ] 책 ID·판본 ID·절 순서·단락의 타입과 검증 규칙 결정.
- [ ] 기존 JSON 변환 및 원문 대조 검수.
- [ ] 스키마·인덱스·공개/관리 RLS 작성, 테스트 DB 구성.
- [ ] 반복 실행해도 중복되지 않는 가져오기와 검증 리포트 작성.
- [ ] 본문 조회 인터페이스를 분리하고 기존 화면을 연결.
- [ ] 기존 기록의 자료·책·버전 매핑을 사전 검사.
- [ ] 백업 → 시험 이전 → 비교 검증 → 복구 연습 → 운영 이전 계획 수립.
- [ ] 첫 DB 배포 시 쓰기 중단 여부·전환 순서·구버전 클라이언트 호환 기간 결정.

스키마 추가와 데이터 검증을 먼저 수행하고 기존 정적 경로 제거는 안정화 이후로 미룹니다.
실패 시 읽기 경로만 되돌릴 수 있는 조건과 새 버전 기록 처리 방법까지 복구 계획에 포함합니다.

## 테스트할 것과 완료 기준

- 동일 검수 버전을 두 번 가져와도 중복 없음. 잘못된 파일은 게시 전 거절.
- 현재 자료의 절 수는 각각 111·111·39이며 순서·장절·본문·단락이 대조 결과와 일치.
- 알려진 판본/책/장/절만 범위 선택 가능. 역순·존재하지 않는 절·다른 판본 혼합 거절.
- 익명/일반 사용자는 초안 읽기·원문 수정·게시 불가. 관리자만 허용된 작업 가능.
- 기존 ID·기록 날짜·사용자 연결·자료별 진행률이 이전 전후 일치.
- 판본별 본문 조회가 섞이지 않음. 응답 지연·조회 실패·계정 전환 때 상태 일관성 유지.
- 고정 자료 버전으로 시험을 시작한 뒤 원문이 새로 게시돼도 해당 시험 기준은 바뀌지 않음.
- 백업 복원과 읽기 경로 복구를 테스트 환경에서 실제 수행.

첫 완료 기준은 검수한 현재 자료를 DB에서 읽어도 사용자 기능과 기존 기록이 유지되는 것입니다.
이 조건을 통과한 뒤 자료 편집 어드민을 연결합니다.

## 결정할 사항

1. 첫 범위: 현재 자료만 / 특정 책 전체 / 성경 전체. 추천은 현재 자료만.
2. 판본 이용 조건: 직접 저장 가능 / 제한된 제공 API 사용 / 판본 변경 필요.
3. 범위 변경: 기존 자료를 변경 / 새 자료 생성. 큰 변경에는 새 자료를 추천.
4. 장기 기록 모델: 하루 한 자료 유지 / 하루 여러 자료 지원. 첫 이전에서는 현행 유지 추천.
