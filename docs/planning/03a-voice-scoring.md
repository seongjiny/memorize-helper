# 3-1. 음성 시험과 점수 설계

상태: 사용자 추가 방향을 반영한 기술·제품 초안. 모델·수치·합격 정책은 아직 검증 전입니다.

## 가능한 것과 모델 운영

녹음한 암송을 이미 학습된 음성 인식 모델로 텍스트로 바꾼 뒤, 선택한 판본의 원문과 비교해
0~100점을 계산할 수 있습니다. 초기에는 별도 모델 학습이나 GPU 서버가 필요하지 않습니다.
OpenAI 같은 음성 인식 API와 채점용 서버리스 함수를 사용하는 접근을 추천합니다.

```text
브라우저: 범위 선택 → 마이크 권한 → 녹음 종료
    ↓ 녹음 파일 + 시도 ID
서버리스 함수: 인증·크기·호출 제한 확인
    ↓ 음성 인식 API 호출
전사문 + 인식 신뢰도 정보(지원될 때)
    ↓ 서버에서 고정된 원문과 비교
점수 + 합격 기준 + 다른 부분 + 판정 상태
    ↓
브라우저: 결과 확인 / 재녹음 / 재연습
```

서버리스 함수는 API 키 보호·비용 제한·일관된 채점을 담당합니다. Supabase Edge Function이
후보이며 런타임의 파일 형식·크기·시간 제한은 실제 녹음으로 검증합니다. 긴 녹음은 절별로 나누거나
비동기 작업이 필요할 수 있습니다. 첫 단계는 녹음을 끝낸 뒤 한 번 전송합니다.

## confidence와 시험 점수의 구분

| 값 | 의미 | 역할 |
| --- | --- | --- |
| 원문 일치 점수 | 인식된 문장이 원문에 얼마나 가까운지 | 70점 같은 합격 기준에 비교 |
| 인식 신뢰도 | 모델이 음성을 해당 문장으로 인식한 결과의 확실성 추정 | 재녹음·불확실 표시의 참고 |
| 녹음 상태 | 무음·잘림·전송 실패 등 | 채점 자체가 가능한지 판단 |

잘못 암송한 문장을 또렷하게 말하면 인식 신뢰도는 높아도 점수는 낮을 수 있습니다.
정확히 말해도 잡음이나 고유어 오인식으로 점수가 낮아질 수 있습니다.
따라서 confidence 0.7을 암송 정확도 70%로 취급하지 않습니다.

Google 문서는 confidence가 없을 수도 있고 정확성이 보장되지 않는다고 설명합니다.
OpenAI의 일부 전사 모델은 토큰 `logprobs`를 제공합니다. 이것도 암송 점수나 보정된
문장 단위 확률이 아닙니다. 여러 모델의 신뢰도 값을 같은 척도로 직접 비교하지 않습니다.
신뢰도가 제공되지 않는 응답을 0으로 간주해 탈락시키지 않습니다.

인식 신뢰도의 사용자 조절은 검증 후 고급 설정으로 검토합니다. 처음에는 앱이 모델별로
검증한 불확실 처리 기준을 사용하고 사용자는 합격 점수를 조절하는 구조를 추천합니다.
음성 감지(VAD) 민감도 역시 마이크의 말하기 감지 기준으로, 암송 정답 기준과 다릅니다.

## 채점 방식 제안

첫 한글 검증은 문장부호·공백 차이를 정규화한 뒤 문자 편집 거리를 사용합니다.
영문은 단어 단위 오류율을 후보로 함께 비교합니다. 한글/영문의 점수를 같은 실력 척도로
해석하지 않고, 각 판본의 실제 녹음으로 문턱을 검증합니다.

```text
N = 정규화한 원문의 문자 수
E = 원문과 전사문을 맞추는 데 필요한 최소 대체 + 누락 + 추가 문자 수
점수 = 100 × max(0, 1 - E / N)
```

예: 원문 100자에서 대체 10자·누락 15자·추가 5자이면 70점입니다.
이 점수는 ‘원문 문자 일치 기반 점수’이며 의미 정확도나 발음 점수는 아닙니다.
한국어 어미·핵심 단어 한 개만 바뀌어도 뜻이 달라질 수 있으므로 다른 부분을 반드시 함께 표시합니다.

정규화 첫 기준:

- 유니코드 NFC, 연속 공백·문장부호 차이 처리. 원문 장절 번호는 비교에서 제거.
- 원문/전사문을 똑같은 규칙으로 정규화하고 화면에는 원래 문장을 보존.
- 한글 어미·부정 표현·의미 있는 단어를 삭제하거나 동의어로 자동 통일하지 않음.
- 원문 전체를 음성 모델 프롬프트로 주어 빈 부분을 복원하게 하지 않음.
  꼭 필요한 언어·용어 안내도 오답을 정답으로 보정하는지 검증.
- LLM에게 문장을 원문대로 고친 뒤 채점하게 하지 않음. 실제 발화가 아닌 정답으로 점수가 올라갈 수 있음.
- 빈 원문은 시험 준비 오류, 무음/빈 전사는 채점 불가로 처리. 잘못된 녹음을 합격시키지 않음.

채점 규칙과 정규화에 버전을 부여합니다. 동일 전사문·원문·규칙 버전이면 점수가 같아야 합니다.

## 합격선과 결과 표시

- 첫 후보는 절별 점수 `>= 70`이면 통과입니다. 70은 사용자가 제안한 출발값이며 실측 후 조절합니다.
- 연습에서는 합격선을 조절할 수 있게 합니다. 시험 시작 시 기준을 고정해 결과에 함께 표시합니다.
- 판정은 반올림 전 값으로 하고 화면 점수는 소수 한 자리 등으로 보여줍니다.
  69.9점을 70점으로 표시해 불합격처럼 보이는 상황을 피합니다.
- 전체 시험은 절별 통과 수와 총 비교 문자 수 기준 점수를 보여줍니다. 짧은 절과 긴 절의
  단순 평균만으로 전체 통과를 판정하지 않습니다.
- 전체 시험 합격 조건은 별도 결정입니다. 예: 모든 절 통과 / 전체 점수 70 이상.
  긴 본문 평균에 특정 절 전체 누락이 가려지는지를 검토합니다.
- 인식 불확실·오디오 불량은 ‘판정 보류’와 재녹음 경로를 제공합니다.
  낮은 점수라는 이유만으로 인식 실패라고 처리해서도 안 됩니다.
- 자동 결과가 잘못된 경우 사용자가 인식문을 확인할 수 있게 합니다. 사용자가 수정한 전사문은
  자기 확인 결과로 구분하고 자동 채점이나 배지 근거와 섞지 않습니다.
- 배지에 시험을 연결한다면 서버에서 정한 고정 조건을 사용합니다. 개인의 쉬운 합격선으로
  공통 실력 배지를 지급할지는 별도로 결정합니다.

결과 예시: ‘원문 일치 82.4점 · 기준 70점 · 통과’와 원문/전사문 차이를 표시합니다.
인식 품질에 근거가 부족하면 꾸며낸 ‘신뢰도 92%’ 숫자를 보여주지 않습니다.

## 저장·비용·구현 범위

- 한 절씩 녹음하고 최대 길이·파일 크기·일일 시도 수를 제한합니다. 실제 값은 샘플에서 결정합니다.
- 서버가 자료 버전과 원문을 선택하고 점수를 계산합니다. 클라이언트가 보낸 점수를 그대로 신뢰하지 않습니다.
- API 키는 서버 설정에만 저장합니다. 새 비용을 발생시키는 API 연결은 실제 구현 범위에서 별도로 구성합니다.
- 앱에서 원본 음성을 장기 보관하지 않는 방향을 추천합니다. 외부 API로 전송되는 사실과 제공사의
  처리/보관 조건은 녹음 기능에서 안내하고 서비스 선정 시 확인합니다.
- 결과를 보관하면 시도 ID·자료/원문 버전·전사문·점수·합격선·규칙/모델 버전·불확실 상태를 저장합니다.
- API 실패·응답 지연·중복 전송에서 재시도와 중복 과금을 줄이는 방식을 검증합니다.

직접 모델 운영은 오픈 모델의 추론 서버·하드웨어·업데이트·관측이 필요한 별도 선택입니다.
기존 모델을 직접 실행하는 것과 다시 학습시키는 것은 다릅니다. 파인튜닝은 사용 동의를 받은
실제 발화/정답 데이터에서 특정 오류가 반복되고, 모델 선택·녹음 개선으로 해결되지 않을 때 검토합니다.
처음 준비할 것은 학습 데이터보다 채점과 인식의 오류를 측정할 평가용 녹음입니다.

## 기술 검증과 테스트

- 한글 판본 우선으로 정상 발화·누락·단어 교체·순서 변경·다른 판본·긴 침묵 샘플 준비.
- 같은 사람이 반복 녹음한 경우와 여러 발화자의 차이를 확인. 말 빠르기·고유어·배경 소음 포함.
- 사람이 적은 실제 발화 전사문과 STT 전사문을 먼저 비교해 인식 오류를 측정.
- 원문 대비 의도적으로 넣은 오류를 모델이 복원하지 않는지 확인.
- 같은 원문에 대해 정답/오답 판정이 사람의 판단과 어느 정도 일치하는지 검토.
  통과해야 할 답의 탈락과 탈락해야 할 답의 통과를 각각 집계.
- 합격선 70 주변의 69.9/70/70.1, 빈 입력, 추가 발화, 전체 절 누락 테스트.
- confidence 누락·높은 confidence의 오답·낮은 confidence의 정답 사례 처리 검증.
- 마이크 거절·iOS/Android 녹음 형식·네트워크 중단·시간 초과·계정 전환 검증.
- 샘플 길이별 비용·응답 시간·점수 흔들림을 비교해 모델과 절별 길이 제한 선택.

첫 완료 조건은 실제 발화에서 설명 가능한 점수와 오답 비교를 제공하고, 불확실한 결과를
확정 판정과 구분하는 것입니다. 사용자 몇 명의 샘플로 조정한 기준은 별도 샘플에서 다시 확인합니다.
