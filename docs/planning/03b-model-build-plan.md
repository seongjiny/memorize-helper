# 3-2. 모델이 없는 상태에서 음성 시험 만들기

상태: 출발 조건을 반영한 작업 계획. 현재 저장소에는 음성 인식 모델·음성 API 연결·채점 모델이 없습니다.
이번 단계는 기획이며 모델 실행, 유료 API 호출, 서버 배포, 학습은 아직 수행하지 않습니다.

## 새로 준비할 구성 요소

| 구성 요소 | 하는 일 | 모델 학습 필요 여부 |
| --- | --- | --- |
| 브라우저 녹음 | 사용자의 암송을 오디오로 수집 | 없음 |
| 음성 인식 | 오디오에서 실제 발화 문장을 얻음 | 기성 모델 사용 시 없음 |
| 원문 정규화·비교 | 원문과 전사문의 누락·추가·교체를 계산 | 첫 편집 거리 방식은 없음 |
| 점수·합격 정책 | 0~100점, 70점 같은 합격선, 불확실 상태 판정 | 규칙으로 구현 가능 |
| 서버 경계 | API 키·인증·호출 제한·자료 버전·채점 보호 | 없음 |
| 평가용 녹음 | 인식 오류와 잘못된 합격/탈락을 측정 | 학습 전에도 필요 |

앱 안에 모델이 없다고 해서 반드시 모델 가중치를 새로 학습해야 하는 것은 아닙니다.
위 전체 파이프라인을 새로 만들되, 음성 인식만 이미 학습된 모델을 사용할 수 있습니다.
채점은 처음부터 학습 모델로 만들지 않고 설명 가능한 비교 규칙을 추천합니다.

## 구현 경로 비교

| 경로 | 준비할 것 | 운영할 것 | 첫 검증 적합성 |
| --- | --- | --- | --- |
| 기성 음성 API | 제공사 선택·계정/API 설정·서버 함수 | API 사용량·비용·제공사 조건 | 가장 빠르게 실제 채점 검증 가능 |
| 기성 오픈 모델 직접 실행 | 모델/라이선스 선택·추론 코드·실행 환경 | 서버·필요한 하드웨어·성능·업데이트 | 외부 API 의존을 줄일 필요가 있을 때 |
| 기성 모델 추가 학습 | 오류 분석·발화/정답 데이터·학습 방식·평가 세트 | 학습 자원과 추론 환경 | 특정 반복 오류가 확인된 이후 |
| 음성 모델 처음부터 학습 | 충분한 음성/전사 데이터·학습 설계·연산 자원 | 연구·학습·추론 전체 | 작은 기능의 첫 구현에는 비용이 큰 별도 프로젝트 |

오픈 모델 직접 실행도 학습과는 다른 작업입니다. CPU 실행 가능성과 실제 서비스 응답 속도는
다르므로 장치·모델 크기별로 검증합니다. GPU 필요 여부는 선택한 모델과 동시 요청 목표에 따라 결정합니다.
API 방식은 별도 GPU 서버 없이 채점용 서버리스 함수부터 시작할 수 있습니다.

## 단계별 계획·목표·테스트

### A. 합격 기준과 샘플 준비

목표: 무엇을 맞췄다고 판단하는지 먼저 정의합니다.

- 현재 한글 자료에서 짧은 절과 긴 절을 선정합니다. 원문·판본·장절을 고정합니다.
- 한 절씩 녹음, 70점 기준, 문자 일치 기반 점수는 시작 후보입니다.
- 정상 암송·누락·핵심 단어 변경·다른 판본·잡음을 포함한 평가 샘플을 준비합니다.
- 실제 발화를 사람이 전사하고 통과/재연습 판단을 별도로 적습니다.
- 녹음 사용 동의와 평가 후 보관/삭제 범위를 정합니다.

테스트/산출물: 판정 기준표, 샘플 목록, 사람 전사문, 기대 결과.
이 데이터는 초기에는 평가용입니다. 나중에 학습에 사용하면 평가용 세트는 따로 유지합니다.

### B. 음성 인식 구성 만들기

목표: 녹음 파일을 넣으면 그 파일의 발화 문장을 얻는 최소 연결을 만듭니다.

- API 또는 오픈 모델 실행 경로를 선택하고 공급자별 차이를 감싸는 인터페이스를 준비합니다.
- 출력은 전사문·지원되는 품질 정보·오류 상태·모델 식별자로 통일합니다.
- 정답 원문을 읽지 않은 부분까지 채워주는 보정은 사용하지 않습니다.
- 실시간 기능 전에 녹음 종료 후 한 번 처리하는 방식을 검증합니다.

테스트/산출물: 같은 샘플의 전사 결과, 사람이 적은 전사문 대비 오류,
무음/잡음/고유어/잘린 음성 처리, 처리 시간·비용 또는 하드웨어 사용량 비교.

### C. 채점 엔진 만들기

목표: 원문과 전사문으로 설명 가능한 동일한 점수를 반복 계산합니다.

- [점수 설계](03a-voice-scoring.md)의 정규화·편집 거리·오답 정렬을 구현합니다.
- 판정 기준과 점수 계산을 분리합니다. 합격선 조절에 모델 재학습은 필요하지 않습니다.
- 원문·전사문·규칙 버전·합격선을 결과에 보존합니다.
- 모델 신뢰도가 불확실하면 재녹음 경로로 분리하고 무조건 낮은 점수로 처리하지 않습니다.

테스트/산출물: 동일/누락/추가/교체/순서 변경 예제, 70점 경계, 공백·문장부호,
반올림, 빈 입력, 의미가 바뀌는 짧은 단어에 대한 검토 결과.

### D. 서버와 시험 화면 연결

목표: 사용자 녹음에서 결과 확인까지 하나의 흐름으로 동작하게 합니다.

- 서버 함수에서 인증·자료 버전·녹음 크기/길이·호출 제한을 검사합니다.
- 브라우저에 공급자 비밀 키를 배포하지 않습니다.
- 녹음 권한·진행·중지·업로드·채점·재녹음 화면과 대체 자기 확인 경로를 만듭니다.
- 연습 합격선을 시험 시작 시 고정하고 점수·기준·오답을 함께 표시합니다.
- 원본 음성 장기 저장과 결과 장기 저장은 각각 필요 여부를 정합니다.

테스트/산출물: iOS/Android/데스크톱 호환, 마이크 거절, 파일 형식,
네트워크 중단, 시간 초과, 중복 요청, 계정 전환, 비용 제한, 키 미노출.

### E. 실측 후 확정

목표: 70점 기준이 실제 암송에서 납득할 수 있는지 확인합니다.

- 사람 판단과 시스템의 잘못된 통과/탈락을 각각 비교합니다.
- 특정 발화자에 맞춘 조정이 다른 발화자에게도 유효한지 별도 샘플에서 평가합니다.
- 인식 오류인지 채점 규칙 문제인지 구분해 개선합니다.
- 합격선·정규화·모델·불확실 처리·녹음 길이 제한을 평가 결과로 확정합니다.

테스트/산출물: 평가 결과표, 선택 모델 근거, 확정 채점 규칙,
응답 시간·사용 비용 예상, 인식 실패 재시도 정책.

## 추가 학습을 선택하면 더 필요한 일

1. 어떤 반복 오류를 해결할지 정의하고 모델이 해당 학습 방식을 지원하는지 확인.
2. 발화/전사 데이터 수집·정제·사용 권한 확보.
3. 같은 발화자가 학습과 평가에 섞여 성능이 과대평가되지 않도록 분리.
4. 학습 환경·실험 기록·비교 기준 모델 준비.
5. 학습하지 않은 새로운 발화에서 개선·성능 저하·잘못된 통과를 함께 평가.
6. 개선된 모델의 추론 서버·버전 배포·되돌리기 준비.

처음부터 학습하는 경우에는 이 목록보다 큰 데이터·연구·연산 계획이 필요합니다.
현 단계에서는 경로를 선택한 뒤 범위를 정하고 견적을 산정합니다.
