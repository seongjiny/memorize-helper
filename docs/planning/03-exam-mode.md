# 3. 시험 모드

상태: 기획 초안. 사용자 추가 방향은 음성 암송을 수치화하고 70점 같은 합격선을 조절하는 방식입니다.
음성 인식과 채점 기준은 [음성 시험·점수 설계](03a-voice-scoring.md)에 별도로 정리했습니다.
현재 모델이 없는 출발 조건과 새로 만들 구성 요소는 [모델 구성 작업 계획](03b-model-build-plan.md)을 참고합니다.

## 목표와 시험 방식 선택

사용자가 어떤 범위를 본문 없이 떠올릴 수 있는지 확인하고, 어려웠던 절을 다시 연습하게 합니다.
결과의 의미가 시험 방식마다 다르므로 먼저 하나를 선택해 사용성을 검증합니다.

| 방식 | 사용자 행동 | 장점 | 추가 설계 |
| --- | --- | --- | --- |
| 자기 확인 암송 | 장절만 보고 암송 → 본문 공개 → 스스로 표시 | 모바일·긴 본문에 적합, 기존 자료로 가능 | 객관적 점수라는 표현을 사용하지 않음 |
| 빈칸 입력 | 일부 단어를 입력 | 짧게 연습 가능 | 빈칸 선정·힌트·한글 띄어쓰기 채점 |
| 전체 타이핑 | 본문 전체 입력 후 비교 | 틀린 위치를 비교 가능 | 긴 입력 부담·정규화·오답 표시 |
| 음성 암송 | 녹음·음성 인식 후 비교 | 실제 암송에 가까움 | 마이크 권한·오인식·저장 정책·비용 |

현재 추천은 짧은 범위를 녹음하는 음성 시험의 기술 검증부터 시작하는 것입니다.
자기 확인 암송은 마이크 사용이 어렵거나 인식 결과가 불확실할 때 대안으로 제공합니다.
공식 합격 판정과 자기 확인 결과는 서로 구분합니다.

## 첫 범위와 사용자 흐름

1. 본문 화면에서 ‘시험하기’ 선택.
2. 자료·판본·범위 확인. 현재 자료 안의 연속 범위를 선택합니다.
3. 준비 화면에서 합격 기준(초안 70점), 녹음·전송, 인식 오류의 확인 방법 안내.
4. 절 번호/장절만 제시 → 녹음 시작 → 암송 → 녹음 종료 → 인식·채점.
5. 결과에서 원문 일치 점수·합격 기준·누락/다른 표현·인식된 문장 확인.
   인식이 불확실하면 점수를 확정하지 않고 재녹음 또는 자기 확인을 안내.
6. 전체 결과에서 절별 점수·재시험 대상·힌트 사용 여부 확인.
7. ‘어려웠던 절 연습’ 또는 ‘다시 시험’ 선택.

첫 단계는 자료 순서대로 한 절씩 진행하고, 랜덤 순서·시간 제한·랭킹은 이후 선택 사항으로 둡니다.
음성 시험은 힌트 없이 시작하는 방향을 추천합니다. 힌트를 추가하면 사용 상태와 결과를 분리합니다.

## 화면 제안

```text
시험 준비
자료: 산상수훈 / 개역개정
범위: 마태복음 5:1–5:12
방식: 음성 / 합격선: 70점      [시작]

암송 확인                    3 / 12절
마태복음 5장 3절
본문 없이 암송해 보세요.
[녹음 시작] → [녹음 종료] → 인식·채점 중

결과
원문 일치 점수 82.4점 / 합격 기준 70점
원문 / 인식된 문장 / 다른 부분
[다시 녹음] [다음 절]

전체 결과
채점 완료 12절 · 통과 8절 · 재연습 4절
[어려웠던 절 연습] [다시 시험] [본문으로]
```

점수는 인식된 문장과 원문의 일치도를 뜻하며 음성 인식 오류의 영향을 받습니다.
자기 확인 대안에서는 자기 평가와 힌트 사용을 보여주고 자동 채점 통과로 표시하지 않습니다.
어려웠던 절이 불연속 범위라면 각 절 목록으로 전달하며 하나의 연속 범위로 합쳐 기록하지 않습니다.

## 상태와 데이터 설계

- 상태 흐름: 준비 → 권한 확인 → 녹음 → 업로드/인식/채점 → 절별 결과 → 전체 결과.
  중간 종료·인식 불확실·통신 실패는 채점 완료와 구분합니다.
- 시험 시작 시 자료·판본·장절·본문 버전을 고정합니다. 진행 중 자료 게시 변경이 결과 기준을 바꾸면 안 됩니다.
- 현재 JSON으로 먼저 구현할 경우 배포 내 본문 스냅샷을 세션에 고정하고 결과를 장기 보관하지 않습니다.
- 음성 API는 비용이 있으므로 첫 유료 API 검증은 로그인과 사용자별 호출 제한을 추천합니다.
  결과 장기 저장 전에는 메모리 내 세션으로 사용성을 확인합니다. 자기 확인 대안은 비로그인도 가능합니다.
- 이탈·새로고침으로 진행이 사라질 수 있음을 준비 화면에 안내하고 진행 중 뒤로 가기/나가기에는 확인을 둡니다.
  브라우저 강제 종료 경고는 보장되지 않습니다. 자동 복구는 별도 기능입니다.
- 재녹음은 새로운 시도이며 이전 점수와 구분합니다. 완료 버튼·응답 재시도로 두 번 집계하지 않습니다.
- 완료 시험은 암송 날짜 기록을 자동 저장하지 않습니다. 사용자가 기존 기록을 수정하는 동작과 분리합니다.
- 계정 변경 시 개인 저장 요청을 중단하고 이전 계정의 시험 상태를 종료합니다.

장기 결과 저장이 필요하면 `exam_sessions`와 `exam_answers`를 별도 테이블로 설계합니다.
자료 버전·범위·방식·힌트 사용·점수·합격선·채점 버전·완료 상태·완료 시각을 저장하고,
본인만 조회/저장할 수 있게 합니다. 서버가 본문 버전과 입력 항목을 검증하며, 제출 ID로 중복 완료를
막습니다. 자기 평가를 저장해도 객관적인 암송 실력으로 해석하지 않습니다.

## 자동 채점 확장 시 정할 것

- 정답 판본과 원문 버전, 문장부호·공백·대소문자 처리, 숫자·따옴표 규칙.
- 한글은 유니코드 정규화를 고려하되 내용이 다른 단어를 느슨한 비교로 자동 정답 처리하지 않습니다.
- 엄격 비교와 참고용 유사도 점수의 의미를 분리합니다. 비교 결과는 원문/입력/틀린 부분으로 보여줍니다.
- 맞춤법·누락·순서·동의어 처리와 힌트 사용 시 점수 정책.
- 시험 결과를 배지에 사용할 경우 서버 채점과 조작 방지 범위. 개인 연습용 결과와 경쟁용 결과의 요구가 다릅니다.
- 음성 방식은 인식 실패를 사용자 암송 실패로 처리하지 않고 다시 입력/자기 확인 경로를 제공합니다.

- [ ] 준비/진행/결과 화면과 이전·다음·중간 종료 동작 구현.
- [ ] 시험 스냅샷·평가·힌트·결과 집계 분리.
- [ ] 음성 API 후보를 실제 녹음으로 비교하고 정규화·점수·합격선 정책 검증.
- [ ] 녹음 권한·브라우저 형식·서버리스 호출·비용 제한·불확실 결과 처리 구현.

- [ ] 장기 결과 저장·실시간 인식·모델 직접 운영은 별도 필요성 검토.

## 테스트할 것과 완료 기준

| 경우 | 기대 결과 |
| --- | --- |
| 마태복음 5:1–12 선택 | 12절을 정확한 순서로 출제 |
| 없는 절·역순·현재 자료 밖의 범위 | 시작 거절과 범위 오류 안내 |
| 시작 직후·절 이동 | 본문이 조기 노출되지 않고 현재 장절만 표시 |
| 자기 확인 대안에서 힌트 후 본문 확인 | 힌트 사용과 자기 평가가 각각 유지 |
| 재녹음·대안 평가 수정·버튼 연속 클릭 | 시도 구분, 결과 중복 집계·중복 완료 없음 |
| 일부 절만 진행하고 종료 | 완료 시험으로 집계하지 않음 |
| 어려웠던 절 재연습 | 해당 절만 포함하며 비연속 목록도 보존 |
| 시험 중 자료 변경·로그아웃 | 잘못된 자료·계정으로 결과 저장 없음 |
| 시험 완료 | 기존 암송 날짜 기록·진행률·달력에 자동 영향 없음 |
| 작은 화면·키보드·스크린 리더 | 현재 절·단계·조작 결과를 알 수 있고 본문 확인 가능 |
| 합격선 70점의 69.9/70.0/70.1 | 표시 반올림에 영향 없이 미통과/통과/통과 |
| 마이크 거절·무음·인식 불확실·API 실패 | 합격/불합격을 임의 판정하지 않고 재시도/대안 제공 |

실제 녹음으로 점수와 오답 위치를 설명할 수 있고, 합격선과 불확실 결과 처리가 일관되며
재연습으로 이어지면 첫 단계 완료입니다. 구체적인 음성 검증 기준은 별도 문서에 있습니다.

## 결정할 사항

1. 방식: 사용자 추가 방향은 음성. 자기 확인은 대안 후보.
2. 진행 단위: 절별 / 단락별. 추천은 절별.
3. 결과 보관: 그 자리에서만 / 로그인 후 장기 저장. 추천은 그 자리에서만.
4. 합격선: 70점을 시작 후보로 검증 / 사용자 조절 범위. 실제 녹음 평가 후 확정.
5. 시험 완료를 꾸준함에 포함할지: 첫 단계는 암송 기록과 분리 추천.
